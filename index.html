A practical working method

Build carefully. Make claims checkable.

For future AI and software work, I want each step to stay easy to inspect: first understand the task, then make a focused prototype, test it, and record the limitations.

01 / CONTEXT

Pull the missing details

Ask who the user is, which inputs exist, what constraints matter, and what a useful result looks like.

02 / DECOMPOSE

Break work into reviewable steps

Separate data preparation, logic, interface, integration, and human review.

03 / SPECIFY

Set an output contract

Define format, evidence needed, unknowns to label, and conditions for a useful answer.

04 / EVALUATE

Check failure cases too

Try representative inputs, inspect errors, and compare results against simple acceptance checks.

This is a proposed working approach and prompt-engineering example. It is not presented as a method already applied in the projects above.
